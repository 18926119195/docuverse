协作与文件管理
1. 先挑仓库和固定提交。PR 写出触发案例、正常入口、模型输入和回包（去凭据）、台账状态、复跑命令及结果。分别标明已运行、源码已接入、模块存在、会话提议。用小提交区分兼容修复与行为实验。
2. 新逻辑按归属沿用当前目录。UI 入口在 src/ui，PDF/OCR 数据流在 src/data，调度和状态在 src/reasoning，已有纯规则在 src/arch，部署 API 在 api，本地适配在 server。早期三库的这些路径在 docuverse/ 下。移动前核对部署根、动态导入、OCR worker、静态资源 URL 和持久化数据。
3. 会话原件留在现有 Git 路径。新原件用完整日期、会话 ID 和原格式；保留发言者、行号及时区。案例写原文指针、实现提交、测试与未决条件，避免复制不同版本的原件。改动配置时沿用服务端环境变量，禁止把测试密钥放进聊天归档或源码。
4. 暂时以本文件作为跨库导航。保留六个运行树各自的部署、提交和聊天源；跨库共用模块一旦有稳定接口及相同夹具，再单独评估提取。当前每库只增加一份维护入口，无目录迁移或运行行为改动。
